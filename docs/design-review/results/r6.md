## 組 A
分數：6 / 10
一句話總評：品牌、熱圖和信任說明都有基本水準，但在 1440p 下大多數頁面只用一條窄欄；候選人頁的載入中與錯誤狀態看起來和正常狀態一樣，空資料也被誤說成「搜尋無結果」，可靠度因此打折。

要保留的優點：
- 議題光譜熱圖（spectrum_desktop、spectrum-dark）：依城市分組，每列用粗框標出該候選人比例最高的議題，色階圖例和「・＝無相關貼文」的說明完整。熱圖用單一紫色色階，沒有用政黨色。
- 議題選擇器結果（policy-results）：每張候選人卡都有大字「議題重合 %」、進度條、各議題比例 chip，以及幾則可連回原文的證據摘要；開頭先說明「不代表立場或支持程度」，中立交代清楚。
- 資料狀態頁頂部（status）：先用一句話給出整體結論（綠色「正常」標籤），再標出快照時間 GMT+8 和排程時段，並說明這是靜態快照、不是即時監控。
- 404（not-found）：大字 404、搜尋框和三個入口按鈕，手機上點擊目標也夠大。
- 手機底部導覽（最新／光譜／選擇器／候選人／更多）和頂部搜尋圖示，全站一致、單手好按。
- 訂閱頁（feeds）：依城市分組的 3×2 卡片排得整齊，RSS／JSON／複製按鈕的位置固定。

最重要的五個問題（由嚴重到輕微）：
1. [cand-loading / cand-error] [兩者] 篩選「捷運」後，載入中狀態沒有任何讀取提示，時間軸和正常狀態完全一樣。錯誤狀態的標頭寫「符合 0 則・顯示 0 則」，下面卻照樣列出舊貼文，也沒有錯誤說明或重試按鈕 —— 使用者會以為篩選已生效，或者看不懂數字和內容為什麼互相矛盾，這是會誤導人的狀態 —— 載入時在時間軸上方加讀取列並淡化舊內容；失敗時顯示紅色說明，寫清楚「下方是先前的貼文，尚未套用篩選」，並附上重試按鈕。
2. [search / about / status / policy-results / spectrum / cand] [desktop] 主內容大多是置中、約 720–1150 CSS px 的窄欄，左側三分之一以上是空白。候選人頁的右側也沒有摘要欄。相反地，首頁 home_desktop 的六欄看板把最右邊的「高雄市」欄裁在視窗邊緣，頁首頭像列也沒有依城市分組 —— 1440p 的空間一邊浪費、一邊溢出，比較候選人時很不方便 —— 把內容放寬到 1400–1600px，讓次要資訊（篩選、統計、計算方式）放在右側欄；首頁欄寬要能容納六欄，或改成可以橫向捲動並給出捲動提示。
3. [search-empty] [兩者] 資料庫沒有資料時，頁面寫「在 0 則候選人官方公開發文中搜尋」，接著顯示「沒有符合『捷運』的貼文，試試較短的關鍵字」，把系統空資料講成使用者的關鍵字問題。status-empty 也只有一行「部分異常」，沒有明說「目前沒有收錄任何貼文」 —— 空資料和查無結果的處理方式應該不同，現在會讓人白白改關鍵字 —— 另做一個空資料狀態：說明資料可能正在重建，提供「查看資料狀態」的連結，並在狀態頁頂部加上醒目的「尚未收錄貼文」說明。
4. [search / search-empty / search-error] [mobile] 城市與平台篩選做成一整排橫向捲動的 chip，卡在畫面右緣（「臺中」之後的城市看不到，「Threads」只露出「Thre」） —— 臺南、高雄、YouTube、X、官網、Podcast 這些選項等於被藏起來，手機使用者不容易發現 —— 改成可以換行的 chip，或收進「篩選」底部面板，並顯示已選數量。
5. [status / status-filter / spectrum / home] [兩者] 細節不一致：status-filter 頂部看不出套用了篩選，跟 status 幾乎一樣；頁首小標用英文的「Status」「Topic spectrum」，和中文介面不搭；狀態頁的元件卡用約 11px 的條列和程式碼字（`overall`、`generatedAt`）直接寫給一般讀者看；每則貼文的動作列把「{} JSON」和「原文」「分享」放在同等位置 —— 字太小、字太淡，工程用語也干擾一般選民閱讀 —— 套用篩選時在頂部顯示篩選摘要和清除按鈕；小標統一用中文；把技術細節收進可展開區塊；把 JSON 降為次要的圖示。

## 組 B
分數：7.5 / 10
一句話總評：寬螢幕用得好，各種狀態都有清楚的說明與下一步，信任資訊也寫得最白話；剩下手機上的密集表格、首頁窄欄的閱讀感，以及狀態頁資訊太多這幾類問題。

要保留的優點：
- 首頁頭像列（home_desktop）依城市分組，右上角用圖例說明「頭像右下的數字＝近 48 小時發文數」。快照時間做成醒目的標籤，六欄看板加上「＋加欄」，1440p 的空間有用到。
- 候選人頁（cand / cand-loading / cand-error）分成時間軸、篩選欄、「30 天發文節奏」長條圖和「議題比例」條四塊。載入中有「正在讀取這位候選人的全部貼文⋯」並淡化舊內容；錯誤時用紅色說明「下方仍是先前顯示的貼文，尚未套用目前的篩選」並附上重試，狀態設計是三組中最好的。
- 搜尋頁（search / search-empty / search-error）用三欄：左側篩選、中間結果、右側「常見關鍵字」。空資料寫「這不是你的關鍵字的問題」，並給出「查看資料狀態」按鈕，和查無結果分得很清楚。手機上的篩選 chip 會換行，所有選項都看得到。
- 資料狀態頁（status / status-filter / status-empty）加了「最新收錄的貼文／這份快照產生於／需要留意的來源」三張白話摘要卡。篩選時頂部有「來源表已篩選・平台：Instagram・符合 15 個來源」，附上跳到來源表和清除篩選的按鈕；空資料時有黃色說明框；工程細節收進「技術細節」，不擋路。
- 議題選擇器結果（policy-results）改成兩欄候選人卡，右側固定一欄「計算方式」，把重合度怎麼算、有什麼限制、不收集隱私資料都講清楚。
- 關於頁（about）有左側本頁目錄、右側「本站概況」數字卡，以及「發現資料有誤？」的回報按鈕。

最重要的五個問題（由嚴重到輕微）：
1. [source-detail] [mobile] 帳號明細表在 390px 寬下硬塞成三欄以上，每列下方留了很大的空白，最右邊的「驗證・佐證」欄被裁在畫面外（另見 source-detail-sparse_mobile；A 組同樣有這個問題） —— 驗證等級是信任的核心資訊，手機上卻看不到 —— 手機版改用每個帳號一張卡：上面是平台圖示和帳號名，下面放角色和驗證徽章；不要用表格。
2. [home / home-dark / home-city] [desktop] 六欄看板每欄只有大約 270 CSS px，中文長貼文每行大約 13 字就換行，大圖幾乎占滿每一欄；欄與欄之間只靠很淡的邊框分隔，掃讀時視線容易跑到別欄 —— 首頁是主要閱讀場景，行長太短讀起來很累 —— 文字預覽限制成 3–4 行、縮小圖片高度或改用縮圖，並加強欄底色和欄標題的區隔。
3. [status / status-dark] [兩者] 狀態頁一路往下依序是三張摘要卡、七張系統總覽卡、八張抓取方式卡、元件狀態和來源表，資訊大量重複（例如「最新收錄 6 小時前」出現兩次）。手機上要捲很遠才看得到各平台 —— 一般讀者只想知道「資料新不新、有沒有缺」，頁面太長會稀釋重點 —— 保留摘要卡和平台表；把系統總覽與抓取方式合併，或預設收合。
4. [search-results / search-filter] [mobile] 篩選 chip 換行後，城市、平台、動機三組大約占掉第一屏一半的高度，結果要往下捲才看得到；常見關鍵字卡也被排在結果或狀態卡的下面 —— 手機搜尋的主角應該是結果 —— 已輸入關鍵字時，把篩選收成一顆「篩選（已選 n）」按鈕，展開後用底部面板呈現。
5. [home / cand] [desktop] 貼文動作列的圖示太小，又很淡：「分享」只有圖示，「{} 資料」縮在右邊角落。熱圖中低比例格子（<3%）的淡紫底配淺色字，對比也偏低（另見 spectrum_desktop 圖例） —— 點擊目標太小，而且部分數字難讀 —— 動作列統一加上文字標籤，按鈕高度至少 32px；淺色格改用深色字。

## 組 C
分數：6 / 10
一句話總評：參考組各自都有成熟的品牌和元件，但截圖裡的首屏被付費牆、廣告和登入限制打斷，就同一把尺來看，可用性起伏很大。

要保留的優點：
- Bluesky 個人頁（bluesky-profile）：頭像、名稱、追蹤數、分頁和貼文的層次清楚，貼文動作列的圖示和數字對齊得很一致，手機上單手也好用。
- Ground News 主題頁（groundnews-interest）：每則新聞都有「左／中／右報導比例條」和來源數，把立場分布做成可以一眼掃讀的小圖，很適合比較類產品參考。
- READr 選舉頁（readr-election）：手機版用左文右圖的清單，日期加上閱讀時間；黃色標題底線和插畫形成鮮明的品牌識別。
- Bluesky 搜尋（bluesky-search）：即使無法使用，也有清楚的標題、原因，以及「登入／建立帳號」的下一步。

最重要的五個問題（由嚴重到輕微）：
1. [groundnews-home] [兩者] 首頁一進去是付費牆插頁：桌面版幾乎整頁空白，只剩被裁切的新聞卡和一顆 Subscribe 按鈕；手機版下半部也一片空白 —— 第一眼完全看不到內容，也不知道網站能做什麼 —— 插頁至少要露出新聞列表的預覽，或者讓「前往首頁」更醒目。
2. [readr-home] [兩者] 桌面版有一個 BytePlus 廣告浮層蓋住頭條圖片，下面還有一大塊橫幅廣告；手機版在頭條後插入 lululemon 和遊戲廣告，打斷文章清單 —— 廣告搶走主視覺，內容的優先順序被打亂 —— 限制廣告的位置，不要蓋在主內容上。
3. [bluesky-search] [兩者] 未登入時搜尋功能完全不能用，桌面版中間欄除了提示以外一片空白，兩側也是大片留白 —— 使用者的任務會在這裡直接中斷 —— 提供有限度的公開搜尋結果，或至少顯示熱門話題作為替代入口。
4. [groundnews-interest] [desktop] 報導比例的文字、標籤和「See the Story」連結約 10–11px，字又淡；比例條很細，而且只靠紅藍顏色區分 —— 核心資訊太小、太依賴顏色，可讀性和無障礙都不足 —— 放大比例文字，並在比例條上直接標示 L/C/R。
5. [readr-election] [兩者] 頁面標題是「所有報導」，內容卻是混合議題，看不出是選舉專題；每篇都寫「閱讀時間 10 分鐘」，缺乏資訊量；分類 tab 用淺灰字，對比偏低 —— 主題頁的定位和篩選回饋都不清楚 —— 加上專題標題與說明，閱讀時間依實際篇幅計算，提高 tab 的對比並標出目前選中的分類。
